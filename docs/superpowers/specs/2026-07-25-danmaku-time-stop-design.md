# 弹幕时停（合并源校时）设计规格

日期：2026-07-25  
组件：`danmakuMerger`  
状态：待用户审查

## 1. 目标

在原生弹幕悬浮菜单中增加「时停 / 恢复」能力。

用户流程：

1. 悬停一条**已合并源**弹幕，点「时停」
2. 同一合并源的弹幕全部高亮并定在原地
3. 其他弹幕暂时隐藏
4. 用户拖动进度条
5. 再点同一按钮「恢复」
6. 系统把进度差写入该源 `offset`，重算并重新注入该源弹幕

成功标准：

- 能用「定住 → 拖进度 → 恢复」完成一次整源时间轴平移
- 与管理面板现有 offset 使用同一字段，恢复后管理面板可见新值
- 不改用户原有播放/暂停状态
- 切视频、切分 P、卸载组件时不会留下脏状态

非目标：

- 不为原生弹幕提供时停
- 不支持多源同时时停
- 不做独立取消按钮
- 不做数字输入式校时主流程（管理面板已有手动 offset）

## 2. 已确认决策

| 项 | 决策 |
|----|------|
| 同来源 | 同一合并源（`sourceId` / BV+源元数据） |
| 入口范围 | 仅合并弹幕显示按钮 |
| 命名 | 空闲「时停」；激活「恢复」 |
| 按钮形态 | 原菜单同一位置切换文案，无第二按钮 |
| 播放状态 | 不改；播着继续播，停着继续停 |
| 其他弹幕 | 时停期间隐藏（含原生 + 其他合并源） |
| 偏移计算 | `newOffset = oldOffset + (t1 - t0)` |
| 场景切换 | 切视频 / 切分 P / 卸载组件 → 丢弃时停，不写 offset |
| 并发 | 全局同时只允许 1 个源；再点其他源时停 = 先丢弃当前再进入新源 |
| 实现路径 | 原生层定格 + 组高亮，不做覆盖层克隆 |

## 3. 用户体验

### 3.1 空闲

- 用户悬停合并弹幕时，原生悬浮菜单最右侧追加「时停」
- 原生弹幕菜单不出现该按钮

### 3.2 进入时停

点击「时停」后：

1. 若已有其他源处于时停：先执行「丢弃」清理
2. 记录：
   - `sourceId`
   - `t0 = 当前播放进度（秒）`
   - 进入时的 UI 标记
3. 画面：
   - 该源弹幕：停止位移/动画，保留当前屏幕坐标
   - 该源弹幕：加高亮边框与轻外发光
   - 其他所有弹幕：隐藏
4. 菜单按钮文案切换为「恢复」
5. 显示实时 `Δ = 当前进度 - t0`（弱提示即可，例如角标或短 toast）

### 3.3 时停中

- 用户可拖动进度条；`Δ` 实时更新
- 时停源弹幕保持钉在进入时的屏幕位置，不跟随时间轴重排
- 播放器播放状态不强制改变
- 再次悬停该源任一条弹幕，菜单仍显示「恢复」

### 3.4 恢复（应用偏移）

点击「恢复」后：

1. `t1 = 当前播放进度`
2. `delta = t1 - t0`
3. `source.meta.offset = (source.meta.offset || 0) + delta`
4. 持久化会话/设置（与现有 saveState / 管理面板同源）
5. 取消高亮与钉住
6. 恢复其他弹幕显示
7. 按新 offset 重建该源弹幕时间，并执行该源注入/同步
8. 清空时停状态机；按钮回到「时停」
9. toast 提示：`已恢复，源偏移 ±x.x 秒`（文案可微调）

说明：

- 不做死区；即使很小的 `delta` 也按累加写入
- 若 `delta === 0`，仍退出时停，但可省略重注入，仅清理 UI 状态

### 3.5 丢弃（不应用偏移）

以下情况执行丢弃：

- 切到其他视频
- 切到其他分 P
- 组件 unload
- 已在时停 A 时，对源 B 发起新的时停（先丢弃 A）

丢弃行为：

1. 不修改任何 `offset`
2. 取消高亮与钉住
3. 恢复其他弹幕显示
4. 清空时停状态机

## 4. 架构

### 4.1 模块边界

建议在 `danmakuMerger` 内新增时停子系统，职责拆分如下：

1. **入口注入器**
   - 往原生弹幕悬浮菜单插入/切换「时停|恢复」
   - 只对可识别合并源弹幕生效
2. **时停状态机**
   - 维护 `idle | active`
   - 保存 `sourceId`、`t0`、钉住快照
3. **画面控制器**
   - 高亮/钉住当前源弹幕
   - 隐藏/恢复其他弹幕
4. **偏移应用器**
   - 计算 delta
   - 更新 `source.meta.offset`
   - 触发该源重建与注入
5. **场景钩子**
   - 监听 `videoChange` / 分 P 切换 / unload，触发丢弃

与现有模块关系：

- 复用 `engine` 的 source 列表与 `meta.offset`
- 复用 `nativeDanmaku` 的注入/同步能力
- 复用管理面板 offset 的数据语义，不新开存储字段

### 4.2 状态模型

```ts
type TimeStopState =
  | { status: 'idle' }
  | {
      status: 'active'
      sourceId: string
      t0: number
      pinned: Array<{
        dmid: string
        // 钉住所需的最小运行时信息（DOM 节点引用或原生对象句柄）
      }>
    }
```

约束：

- 全局唯一 `TimeStopState`
- `active` 时禁止再并行创建第二个 active（遇新请求先 discard）

### 4.3 数据流

```text
悬停合并弹幕
  → 识别 sourceId
  → 菜单显示「时停」

点击时停
  → discard 旧状态（如有）
  → 记录 t0
  → hideOthers()
  → pinAndHighlight(sourceId)
  → 按钮改「恢复」

拖动进度
  → Δ = now - t0（仅展示）

点击恢复
  → offset += now - t0
  → save
  → unpin/showOthers
  → rebuild+inject source
  → idle

切视频/分P/unload
  → discard（不写 offset）
```

## 5. 识别与注入细节

### 5.1 如何识别合并弹幕

现有合并弹幕 dmid 使用前缀 `dmmerger_`。

识别优先级：

1. dmid 前缀解析出 sourceId
2. 若运行时对象带有源元数据，直接读 sourceId
3. 都失败：不显示「时停」

### 5.2 菜单注入

- 挂在原生弹幕 tip / 悬浮功能组
- 仅追加一项，不改点赞/复制/举报
- 文案：
  - idle：`时停`
  - active 且 source 匹配：`恢复`
  - active 但悬停的是其他合并源：显示「时停」（点击会切换源：先 discard 再进入）

### 5.3 钉住与高亮

推荐实现顺序：

1. 收集当前源所有可见弹幕节点/对象
2. 暂停其动画（Web Animations / transform 动画）
3. 固化当前 `transform/left/top` 到固定坐标
4. 加 class：`dm-merger-time-stop-active`（名称可在实现时微调）
5. 其他弹幕加隐藏 class：`dm-merger-time-stop-hidden`

样式基线：

- 描边 2px
- 轻微外发光
- 不改变字号与颜色本体，避免可读性骤降

若原生动画无法稳定暂停：

- 回退方案 B（克隆覆盖层）仅作为实现兜底，不作为产品默认

### 5.4 隐藏其他弹幕

隐藏范围：

- 原生弹幕
- 其他合并源弹幕

保留范围：

- 当前时停源弹幕

恢复时必须成对清理隐藏 class / 显示状态，避免泄漏。

### 5.5 偏移应用

```text
oldOffset = Number(source.meta.offset) || 0
delta = t1 - t0
source.meta.offset = oldOffset + delta
```

随后：

1. `rebuildListMeta` 或等价逻辑，把 offset 作用到该源时间
2. 对该源执行 purge+inject / fullSync 子集更新
3. 管理面板 offset 输入显示新值

单位：秒（与现有管理面板一致）。

## 6. 错误处理

| 情况 | 行为 |
|------|------|
| 悬停项不是合并弹幕 | 不显示按钮 |
| 进入时停时 sourceId 丢失 | toast 失败，不进入 active |
| 钉住失败（找不到节点） | 不进入 active，toast「无法时停该弹幕」 |
| 恢复时 source 已不存在 | discard UI，toast「源已移除」 |
| 注入失败 | offset 已写入时保留数值，并 toast 提示可到管理面板重试同步 |
| 时停中列表/画面被播放器重建 | 尝试按 sourceId 重钉；失败则 discard 并提示 |

## 7. 测试要点

### 功能

1. 合并源弹幕悬停有「时停」；原生无
2. 时停后同源弹幕高亮且位置固定
3. 其他弹幕全部隐藏
4. 拖进度后点恢复，offset 按 delta 累加
5. 管理面板显示同一 offset
6. 再次时停同一源，可继续累加
7. 时停 A 时再时停 B：A 丢弃，B 进入
8. 切分 P / 切视频：状态丢弃，offset 不变
9. 恢复后其他弹幕重新出现，无残留高亮

### 交互/样式

1. 菜单项不挤爆原生 tip
2. 高亮边框在深浅背景下都可见
3. 播放中进入时停，播放状态不被强制切换
4. 暂停中进入时停，仍保持暂停

### 回归

1. 管理面板手动改 offset 仍可用
2. 会话恢复不因时停状态机报错
3. pakku 兼容路径不被破坏

## 8. 实现分期建议

### P0（必须）

- 菜单注入：时停/恢复切换
- 单源状态机
- 钉住 + 高亮 + 隐藏其他
- 恢复写 offset 并重注入
- 场景切换 discard

### P1（增强）

- 实时 Δ 显示
- 钉住失败重试
- 更稳的原生动画适配

### 不做

- 多源并行时停
- 原生弹幕时停
- 独立取消按钮
- 死区逻辑

## 9. 开放实现细节（不阻断规格）

以下可在实现阶段按原生 DOM 实测定夺，不改变产品行为：

- 菜单挂载选择器与事件委托位置
- 钉住时用 WAAPI `pause()` 还是固化 transform
- 隐藏用 class 还是 `visibility/display`
- toast 文案最终措辞
